# ADR checks for direct pushes to `main`

Validate ADRs created with `create-adr-md` before and after a push.

1. **Local `pre-push`** validates added and changed ADRs. All new code commits in a push must be referenced by a new ADR committed **later in the same push**. Errors block the push.
2. **GitHub Actions `push`** validates ADRs in `HEAD` and checks recent code commits. It reports invalid ADRs and missing references in warnings and the Actions run **Summary**. Warnings keep the job successful.

Both scripts use `create-adr-md/scripts/validate-adr.mjs`. Requires Git and Node.js 18+.

## Install

Copy this `create-adr-md/` directory into the target repository root. Copy the contents of its `.github/` and `.githooks/` directories into the matching directories at that root. The hook and CI load the validator at `create-adr-md/scripts/validate-adr.mjs`. Commit the skill directory and the installed files so GitHub Actions can read them.

The target repository must contain these files.

```text
.githooks/pre-push
.github/scripts/adr-validation.mjs
.github/scripts/check-adr.mjs
.github/scripts/audit-adr.mjs
.github/workflows/adr-check.yml
create-adr-md/scripts/validate-adr.mjs
```

Run these commands in the target repository on each developer computer.

```sh
git config core.hooksPath .githooks
chmod +x .githooks/pre-push
```

Make sure the hook is committed as executable (`git update-index --chmod=+x .githooks/pre-push`). Git hooks are not automatically installed on other clones; each machine must set `core.hooksPath`.

Edit `CODE_PATHS` in `.github/scripts/adr-validation.mjs` if the code lives outside `src/`, `app/`, `lib/`, `test/`, `tests/`.

The hook passes the push remote name to the validator. GitHub Actions uses `origin` through `ADR_REMOTE` in the workflow. Both require a configured Git remote and full local implementation commits.

## Normal workflow

```sh
# Commit A: implementation
git add src/ tests/
git commit -m 'fix: synchronize cache'
git rev-parse HEAD  # copy the full SHA
```

Create `docs/adr/0042-cache-sync.md` with the `create-adr-md` template.

```markdown
# ADR-0042: Cache synchronization

**Status:** Accepted
**Date:** 2026-11-17
**Record Type:** Agent-Session
**Evidence:** Agent Session

## Context
Concurrent cache updates can conflict.

## Decision
Use a mutex for cache updates.

## Rationale
A queue would add complexity with no benefit for the current workload.

## Alternatives
Not recorded.

## Consequences
Cache updates run one at a time.

## Implementation
Cache updates use the same mutex.

## Implementation Commit
- https://github.com/OWNER/REPO/commit/0123456789abcdef0123456789abcdef01234567
```

Replace the example prose, date, repository URL, and SHA with verified values. Add one URL bullet for each implementation commit. Full SHAs can contain 40 or 64 hex characters. Then run these commands.

```sh
node create-adr-md/scripts/validate-adr.mjs docs/adr/0042-cache-sync.md --repo . --remote origin
git add docs/adr/0042-cache-sync.md
git commit -m 'docs: record cache synchronization ADR'
git push origin main
```

- The hook blocks the push if commit A is not covered by a new ADR in commit B.
- GitHub Actions audits recent commit history and reports missing ADR links and invalid ADRs.

Run the regression checks from the target repository root.

```sh
node --test create-adr-md/tests/adr.test.mjs
```

## Important details

- The Actions scan checks the **last 30 non-merge commits**, including earlier pushes. Change `ADR_SCAN_LIMIT` in `.github/workflows/adr-check.yml` if needed (1–500).
- Every `.md` file under `docs/adr/` must use the new template and the path `docs/adr/NNNN-lowercase-slug.md`. References are URL bullets in `## Implementation Commit`.
- Store each ADR as a regular file. Give all four metadata attributes non-empty values.
- The title can contain at most 120 characters. The 350-word prose budget covers the title and the text in Context, Decision, Rationale, Alternatives, Consequences, and Implementation.
- The scripts validate a temporary copy of `docs/adr/` from the checked commit. The validator uses the source repository's Git objects and remote settings. It checks content and duplicate IDs against that committed tree. Local file and index changes do not affect validation.
- `Agent-Session` and `Retrospective` ADRs can reference earlier commits already in `main`. Each reference must precede the commit that last changed the ADR. The audit counts each linked commit as covered when it also precedes the ADR's addition. Other valid links can be added during later edits.
- A missed ADR can be committed later (for example after bypassing the hook). The **next** Actions run will no longer list the implementation commit, provided it is within the scan window. Old Actions run summaries are immutable.
- Review **Actions → ADR audit (main) → Summary** or the annotation log.
- A `git push --no-verify` can bypass the local hook. GitHub Actions detects the missing reference **after** the commit reached `main`.
- Each new code commit still needs a new ADR added later in the *same push*. The ADR and its reference must remain present at the pushed revision. A standalone ADR for an earlier push is allowed.
- Keep the history linear and avoid rebase/squash after the ADR references an implementation SHA: rewritten commits invalidate SHA links.
- Review factual accuracy and ASD-STE100 wording separately from automated validation.

## Files

- `.githooks/pre-push` runs the blocking hook.
- `.github/scripts/check-adr.mjs` checks the push.
- `.github/scripts/adr-validation.mjs` calls the validator and defines code paths.
- `.github/workflows/adr-check.yml` runs the GitHub Actions audit.
- `.github/scripts/audit-adr.mjs` audits recent commits.
