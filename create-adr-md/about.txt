# ADR checks for direct pushes to `main`

Validate ADRs created with `create-adr-md` before and after a push.

1. **Local `pre-push`** validates new and changed ADRs in the pushed tree. Invalid ADRs stop the push. The hook lists new code commits without valid ADR links and asks for confirmation once.
2. **GitHub Actions** runs on pushes to `main` and on demand. It warns about code commits without valid ADR links and lists links to those commits in the run **Summary**. The audit stays successful.

Both scripts use `create-adr-md/scripts/validate-adr.mjs`. Requires Git and Node.js 18+.

## Install

Copy `create-adr-md/`, `.github/`, and `.githooks/` from the root of this package into the target repository root. Merge the contents with existing directories and files; do not replace the directories. The hook and CI load the validator at `create-adr-md/scripts/validate-adr.mjs`. Commit the skill directory and the installed files so GitHub Actions can read them.

The target repository must contain these files.

```text
.githooks/pre-push
.github/scripts/adr-policy.mjs
.github/scripts/check-adr.mjs
.github/scripts/audit-adr.mjs
.github/workflows/adr-check.yml
create-adr-md/scripts/validate-adr.mjs
create-adr-md/templates/adr.md
create-adr-md/references/types.md
```

Run these commands in the target repository on each developer computer.

```sh
git config core.hooksPath .githooks
chmod +x .githooks/pre-push
```

Make sure the hook is committed as executable (`git update-index --chmod=+x .githooks/pre-push`). Git hooks are not automatically installed on other clones; each machine must set `core.hooksPath`.

Set the shared `CODE_PATHS` in `.github/scripts/adr-policy.mjs` to the target repository's relative code paths, for example `["Sources/", "main.swift", "Package.swift"]`. This package includes `.github/scripts/`, `.githooks/`, `create-adr-md/scripts/`, and `create-adr-md/tests/`. An empty or invalid list skips the commit scan. The hook still validates new and changed ADRs.

The hook passes the push remote name to the validator. GitHub Actions uses `origin` through `ADR_REMOTE` in the workflow. Both require a configured Git remote and full local implementation commits.

## Normal workflow

Offer an ADR when a technical decision and its reasons are confirmed. The user can defer it. If the same decision already has an ADR, update that file: keep its ID, creation date, and valid links, then add the new facts and commit links. A new decision gets a new ADR. Do not create one ADR per code commit.

When the user chooses to record a decision, commit its implementation before the ADR.

```sh
# Commit A: implementation
git add src/ tests/
git commit -m 'fix: synchronize cache'
git rev-parse HEAD  # copy the full SHA
```

Create `docs/adr/0042-cache-sync.md` with the `create-adr-md` template.

```markdown
# ADR-0042: Cache synchronization

**Status:** Accepted
**Date:** 2026-11-17
**Record Type:** Agent-Session
**Evidence:** Agent Session

## Context
Concurrent cache updates can conflict.

## Decision
Use a mutex for cache updates.

## Rationale
A queue would add complexity with no benefit for the current workload.

## Alternatives
Not recorded.

## Consequences
Cache updates run one at a time.

## Implementation
Cache updates use the same mutex.

## Implementation Commit
- https://github.com/OWNER/REPO/commit/0123456789abcdef0123456789abcdef01234567
```

Replace the example prose, date, repository URL, and SHA with verified values. Add one URL bullet for each implementation commit. Full SHAs can contain 40 or 64 hex characters. Then run these commands.

```sh
node create-adr-md/scripts/validate-adr.mjs docs/adr/0042-cache-sync.md --repo . --remote origin
git add docs/adr/0042-cache-sync.md
git commit -m 'docs: record cache synchronization ADR'
git push origin main
```

- The hook checks new non-merge commits in `CODE_PATHS` between the remote tip of `main` and the pushed SHA. The first push to `main` checks the full pushed history. The hook reads ADRs from the final pushed tree.
- Enter `y` or `yes` at the terminal to accept the listed commits. A refusal, an empty reply, or end of input stops the push.
- Without a terminal, use `ADR_ALLOW_MISSING=1 git push origin main` to confirm missing ADR links. Validation errors in new or changed ADRs still stop the push.

Run both regression suites from the target repository root.

```sh
node --test create-adr-md/tests/*.test.mjs
```

## Important details

- The audit scans the **last 30 non-merge commits**, including earlier pushes, for changes in `CODE_PATHS` without links from valid ADRs. Each unlinked code commit produces a warning with its full SHA and URL. Change `ADR_SCAN_LIMIT` in `.github/workflows/adr-check.yml` if needed (1–500).
- Every `.md` file under `docs/adr/` must use the new template and the path `docs/adr/NNNN-lowercase-slug.md`. Commit references are URL bullets in `## Implementation Commit`. Source symbols use the optional table in `## Related Symbols`; allowed types come from `create-adr-md/references/types.md`.
- Store each ADR as a regular file. Give all four metadata attributes non-empty values.
- The skill requires a title of at most 120 characters and a 350-word prose budget across the title, Context, Decision, Rationale, Alternatives, Consequences, and Implementation. Review language and length manually. The validator checks structure, literal unfilled template fields, commit links, and the `Related Symbols` table.
- The scripts validate a temporary copy of `docs/adr/` from the checked commit. The validator uses the source repository's Git objects and remote settings. It checks content and duplicate IDs against that committed tree. Local file and index changes do not affect validation.
- `Agent-Session` and `Retrospective` ADRs can reference earlier commits already in `main`. Each reference must precede the commit that last changed the ADR. Links added during later edits are valid on the same terms.
- An ADR can be committed or updated later. The next audit omits its valid linked commits from warnings. Old Actions run summaries are immutable.
- Review **Actions → ADR audit (main) → Summary** or the annotation log.
- A `git push --no-verify` bypasses the local hook.
- On the first push to `main`, the hook validates all ADRs in the pushed tree. The audit checks links from valid ADRs in `HEAD`.
- Merge commits are supported. Rebase, amend, and squash can change implementation SHAs; verify and update affected ADR links after those operations.
- Review factual accuracy and ASD-STE100 wording separately from automated validation.

## Files

- `.githooks/pre-push` runs the blocking hook.
- `.github/scripts/adr-policy.mjs` defines the code paths for both checks.
- `.github/scripts/check-adr.mjs` checks the push.
- `create-adr-md/scripts/validate-adr.mjs` provides CLI and committed-tree validation.
- `create-adr-md/references/types.md` defines source symbol types by language.
- `.github/workflows/adr-check.yml` runs the GitHub Actions audit.
- `.github/scripts/audit-adr.mjs` reports code commits without valid ADR links.
